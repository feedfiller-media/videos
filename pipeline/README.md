# Daily cutting videos for @thefeedfiller

`python3 pipeline/run.py YYYY-MM-DD` renders two "1 cut vs 1000 cuts" videos (about 29 s each, loop format,
knife in the first frame), writes them to the repo root as `YYYY-MM-DD_1_<fruit>.mp4` and `YYYY-MM-DD_2_<fruit>.mp4`,
and writes `plan.json` with the caption and time slot (12:45 and 19:45 Europe/Berlin) for each.

Each fruit folder in `pipeline/fruits/` is a self-contained renderer (moderngl, EGL, numpy, scipy, Pillow, ffmpeg).
Per video the end question, camera angle and collapse simulation are randomised, so no two posts are identical.

## Content safety
- Sound: knife knocks cut from a Pixabay recording (Pixabay Content License, commercial use allowed, no attribution needed).
- Font: Poppins (SIL Open Font License).
- Everything else (models, textures, wall, board, "thefeedfiller" branding) is generated by code. No logos, brands,
  music, people or third-party footage.
- Captions are plain English with generic hashtags.

## Daily job (scheduled task, 8:47 Europe/Berlin)
The daily session analyses Buffer metrics, appends a snapshot to `pipeline/stats.json`, writes its reasoning to
`pipeline/log.md` and then runs `FRUIT_1=<proj> FRUIT_2=<proj> END_1="..." END_2="..." python3 pipeline/run.py <today>`.
Rules for the analysis:
- A video counts fully after 48 h; videos from yesterday count as an early signal only (low weight), compared
  with other videos at the same age using the stored snapshots.
- Views never go down: keep the highest value seen; drops or zeros from Buffer are treated as errors.
- Values unchanged for several days are probably stale and count weakly.
- Compare relatively (rank), change weights slowly, never drop a fruit after one weak video, keep some exploration.
- Without usable data, fall back to the normal rotation. Kevin's screenshots override Buffer numbers.
Video files live only on the `uploads` branch and are removed (orphan rebuild, force push) once Buffer reports them as sent.
